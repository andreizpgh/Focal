# Prompt for the next Codex session

Продолжи разработку Focal: https://github.com/andreizpgh/Focal,
ветка `codex/sessions-stt-handoff`, существующий draft PR #1. Работай с последним
состоянием этой ветки. Архив из предыдущего чата не нужен: утверждённый логотип,
его исходники, приложение и документация находятся в репозитории.

Сначала прочитай `AGENTS.md`, `docs/development-handoff.md`,
`docs/quality-report.md`, `docs/architecture.md`,
`docs/stt-quality-experiments.md` и `docs/device-validation.md`.

Дизайн выбран: D / Sessions, светлая тема с чёрными акцентами, тихий интерфейс.
Логотип Focus wave утверждён; исходники и инструкция — `design/brand/`.
Не возвращайся к поиску нового лого. Сохрани расфокус основной иконки и
функциональные анимации уровня записи/обработки; не добавляй декоративные
заставки, бренд в шапку Sessions и лишний поясняющий текст под Record.

Основной незакрытый приоритет — измеримое качество и скорость локального STT.
Пользователь тестировал на русском, но качественно должны работать все семь
поддерживаемых языков. Прошлые UI/синтетические тесты не измеряли точность речи.
Проверь фактическую сетевую политику новой среды: настройки для Hugging Face
пользователь опубликовал, но предыдущая уже запущенная среда оставалась на старой
политике. Не пытайся обходить запрет сети.

Общий лимит загрузки моделей и корпуса — 1 000 000 000 байт, включая повторы.
Сначала метаданные, лицензии, фиксированные ревизии/хэши; затем только выбранные
небольшие аудиопримеры, без полных шардов корпуса. Начни с базовой модели и
реальных пропущенных JNI/workflow-проверок, затем проведи парные измерения
WER/CER по плану экспериментов. Сравни модели/квантование, акустический второй
проход и настройки сегментации/контекста. Меняй архитектуру или модель, если
это оправдано измерениями, и проводи нужную адаптацию Android, а не только
host-эксперимент.

Можно исследовать локальную модель точечных исправлений, но включать её только
при подтверждённом улучшении на отложенных данных и приемлемой цене для телефона.
Особенно контролируй имена, числа и отрицания. Сохраняй исходную ASR/аудиозапись,
ручные правки, происхождение исправлений и Undo; для этого потребуется отдельная
модель данных, описанная в плане. Не выдавай уверенность LLM за доказательство.

Продолжай автономно до проверяемого результата. Проведи независимое code review
изменённых слоёв через параллельных GPT-6.1 Sol xhigh / Terra агентов, исправь
подтверждённые замечания, выполни релевантные тесты и обнови отчёт. Указывай
отдельно измеренное, проверенное на эмуляторе и требующее реального ARM64-телефона.
Не называй приложение полностью готовым и не заменяй опубликованный APK, пока
не закрыты реальные quality/device/signing gates. В конце зафиксируй и отправь
проверенные изменения в эту ветку и обнови draft PR и handoff.
